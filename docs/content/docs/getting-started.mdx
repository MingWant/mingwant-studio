# 零基础快速开始

本教程帮助第一次接触明想 MingWant Studio 的用户，从启动系统走到完成第一条可追踪的生成任务。完成后，你应该能够登录、配置模型、创建画布、生成内容、查看任务状态并导出画布备份。

> 当前项目尚未完成构建、浏览器和生产部署验证。第一次使用请放在本机或可信测试环境，不要直接把未验收实例用于正式广告交付。

## 一、先选一种运行方式

| 目标 | 推荐方式 | 需要准备 | 入口 |
| --- | --- | --- | --- |
| 只想尽快体验完整系统 | Docker Compose | Docker Desktop 或 Docker Engine + Compose | `http://localhost:3000` |
| 要修改前后端代码 | 本地开发 | Go 1.25、Bun、Git | `http://localhost:3000` |
| 部署到 Linux 服务器 | 源码或镜像部署 | Linux、域名、HTTPS、持久化备份方案 | 见[管理部署手册](administration-deployment.mdx) |

文本、图片、音频和视频任务都由 Web 提交到后端任务队列，再由正确配置的模型渠道执行。

## 二、启动前检查

### 1. 端口

默认会使用以下端口：

- `3000`：明想 Web 页面。
- `8080`：后端 API。只有源码开发时直接监听宿主机，本地 Vite 会自动代理 `/api`；Docker 方式不会把它单独发布到宿主机，统一从 Web 地址下的 `/api` 访问。

端口被占用时，先停止冲突程序或按配置同步修改服务和代理；不要只改其中一端。

### 2. 模型服务

至少准备一个可用的模型服务，并确认你知道：

- Base URL；
- API Key；
- 模型标识；
- 模型的真实请求协议；
- 账户额度和供应商的内容、并发及地区限制。

建议第一次只配置一个文本模型，完成最小生成验证后再接入图片和视频，排错会更直接。

### 3. 数据目录

后端数据库、上传资源和存储加密密钥必须放在持久化目录中。不要今天用一个目录、下次又从另一个目录启动，否则会看起来像“账号和数据消失”。

Docker 命名卷还会绑定 **Compose 项目标识**。仓库目录改名、从另一个目录执行，或修改 `COMPOSE_PROJECT_NAME`，都可能让同一个 `backend-data` 逻辑卷变成另一套实际卷。Windows 启动脚本会在首次健康启动后把当前标识写到 `.local/compose-project-name`；后续发现标识变化会在创建或修改容器前停止。这个文件只记录项目名，不包含密钥。不要为了越过提示直接删除它，应先恢复原目录名或原 `COMPOSE_PROJECT_NAME` 并找回原卷。

全新安装若打算长期使用手工 Compose，可在**第一次启动前**于根目录 `.env` 固定：

```dotenv
COMPOSE_PROJECT_NAME=mingwant-studio
```

已经有数据的安装不要照抄这个值；先用原目录和原环境确认既有项目名，之后始终沿用。

本仓库维护工作区有一条额外约束：脱离 Docker 启动后端时，必须先检查并继续使用 `.local/project-workbench-debug`，不得直接使用 `backend/data` 创建另一套本地账号数据。

```powershell
# 在仓库根目录执行；先确认其中已有哪套数据库和资源。
Get-ChildItem .local\project-workbench-debug -Force
```

如果这个维护目录不存在，不要擅自创建替代数据库，应先确认要恢复的数据来源。全新、独立的安装可以自行选择一个专用持久化目录，但选定后也应固定使用。

## 三、方式 A：Docker 一次启动

Windows PowerShell 推荐在仓库根目录执行启动检查脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

脚本会在构建前区分“没有安装 Docker”“Docker Desktop/Engine 尚未启动”“当前账号无权访问 Docker Engine”“Compose 不可用”和“Web 端口被占用”，启动后按最多 30 秒重试数据库、运行时协调器与 Worker 健康检查。端口冲突会在创建或修改本项目容器前停止，并显示占用进程。它不会自动启动 Docker Desktop，也不会删除任何卷。

脚本还会打印当前 Compose 项目标识。第一次健康启动后请保留 `.local/compose-project-name`；如果以后提示标识变化，说明继续操作可能看到一套空数据库，应先恢复原标识而不是重新注册账号。

默认使用 `3000`。如果该端口确实要留给其他程序，可在当前 PowerShell 会话改用另一个端口：

```powershell
$env:CANVAS_HTTP_PORT = "3001"
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

也可以在仓库根目录 `.env` 中固定写入 `CANVAS_HTTP_PORT=3001`。端口必须是 1 到 65535 的整数；脚本最终打印的网页地址和健康检查地址会自动使用同一个值。

macOS、Linux 或需要手工执行时使用：

```bash
docker compose -f docker-compose.local.yml up -d --build --wait
docker compose -f docker-compose.local.yml ps
```

Web 依赖默认从 `https://registry.npmjs.org` 安装，避免锁文件中的开发镜像 CDN 不稳定。若所在网络必须使用其他可访问的 npm 注册表，可在当前 PowerShell 会话临时指定：

```powershell
$env:NPM_REGISTRY = "https://你的可用 npm 镜像"
docker compose -f docker-compose.local.yml up -d --build --wait
```

启动成功后：

1. 打开脚本最终显示的地址；未改端口时是 `http://localhost:3000`。
2. 后端数据保存在 `backend-data` 卷。
3. 打开脚本所用地址下的 `/api/health`（默认是 `http://localhost:3000/api/health`），确认 `database`、`coordination` 和 `worker` 都是 `ok`；仅看到容器处于 `Up` 不能证明生成任务可用。

Docker 模式不要用 `http://127.0.0.1:8080` 判断后端是否存活；该端口只在容器网络内提供给 Web。宿主机统一检查 `http://localhost:3000/api/health` 或实际 Web 端口。

如果要让同一局域网的另一台电脑或手机访问，把 `localhost` 换成运行 Docker 主机的局域网 IPv4 地址，例如 `http://192.168.1.20:3000`；端口以脚本最终显示的值为准，并在 Windows 防火墙中允许该端口。首次注册、登录和打开画布都使用同一个地址，不要在 `localhost`、`127.0.0.1` 和局域网 IP 之间来回切换。局域网 HTTP 适合可信测试网络，API Key 仍只交给可信的自部署后端；正式使用请放到 HTTPS 反向代理后。部分浏览器在局域网 HTTP 下不提供 `crypto.randomUUID()` 或 `crypto.subtle`，当前版本已为本地 Agent、画布事件和影视入口提供不含密钥的降级标识，但这不等同于 HTTPS 的安全边界。

停止服务但保留数据：

```bash
docker compose -f docker-compose.local.yml stop
```

再次启动：

```bash
docker compose -f docker-compose.local.yml start
```

不要执行 `docker compose down -v`。`-v` 会删除后端数据卷，可能同时清除账号数据和上传资源。

## 四、方式 B：本地开发启动

### 1. 启动后端

Windows PowerShell，在仓库根目录执行：

```powershell
Get-ChildItem .local\project-workbench-debug -Force
$projectDataPath = (Resolve-Path ".local\project-workbench-debug").Path
Set-Location backend
$env:CANVAS_BACKEND_DATA_DIR = $projectDataPath
go run ./cmd/server
```

macOS 或 Linux，在仓库根目录执行：

```bash
test -d .local/project-workbench-debug
cd backend
CANVAS_BACKEND_DATA_DIR="../.local/project-workbench-debug" go run ./cmd/server
```

看到 `MingWant Studio backend listening on :8080` 后，另开终端继续启动 Web。可以打开 `http://127.0.0.1:8080/api/health`，正常响应应包含 `status: ok`，并且 `database`、`coordination`、`worker` 三项均为 `ok`。

### 2. 启动 Web

```bash
cd web
bun install
bun run dev
```

打开 `http://localhost:3000`。本地开发服务器会把 `/api` 请求转发到 `127.0.0.1:8080`。

## 五、注册第一个管理员

1. 打开 `http://localhost:3000/register`。
2. 填写账号信息并提交。
3. 数据库中的第一个账号会自动成为管理员，首次注册不要求邮箱验证码。
4. 登录后确认能够进入“管理后台”。

环境变量默认关闭普通注册，但不会阻止空数据库创建首个管理员。创建管理员后，再到“管理后台 → 登录与注册”决定是否开放普通注册；如果要求邮箱验证码，还必须先配置可用的 SMTP 邮件服务。

如果页面没有把首个账号识别为管理员，先停止继续注册，并确认后端是否误用了另一套数据库目录。

## 六、配置第一个模型渠道

系统有两种渠道：

- **自定义渠道**：每个用户在自己的“配置与用户偏好”中保存。API Key 默认只保留在当前标签页会话；刷新页面仍可使用，退出登录或关闭标签页后清除。只有用户在可信个人设备上明确开启“在此设备记住”，密钥才进入独立的账号级浏览器持久区。异步任务可能把所选渠道密钥加密后交给可信自部署后端执行。
- **系统渠道**：管理员统一保存渠道、模型、售价和并发策略，普通用户通过积分使用。系统渠道的测活会写入共享模型状态，只有管理员能发起测活；普通用户直接使用管理员已经发布的能力结论。

第一次验证建议先用自定义渠道，配置路径更短。

浏览器不会直接向第三方供应商创建图片、视频或音频，也不会在页面里轮询这些上游任务。媒体生成统一先创建 MingWant Studio 后端持久化任务，由 Worker 调用供应商、记录计费边界并跨刷新恢复；在线 Agent 文本和“拉取模型”则通过登录态同源中继。正常情况下浏览器开发者工具里只应看到当前 MingWant Studio 域名，不需要给每个供应商单独配置浏览器 CORS。

### 1. 新增自定义渠道

1. 打开“配置与用户偏好 → 自定义渠道”。
2. 点击“新增渠道”。
3. 填写渠道名称，例如“OpenAI 官方”或“我的 NewAPI”。
4. 选择默认模型协议。
5. 填写 Base URL。OpenAI 官方默认是 `https://api.openai.com`，Gemini 官方默认是 `https://generativelanguage.googleapis.com`；也可以明确填写供应商给出的 `/v1` 或 `/v1beta` 版本根地址，系统不会重复追加版本路径。若 Postman 使用的是 `https://host/v1/chat/completions`，这里只填 `https://host` 或 `https://host/v1`，不要把 `/chat/completions` 一起填入。其他网关必须使用供应商实际提供的根地址。
6. 填写 API Key。默认使用会话保存；只有这是可信的个人设备且你接受浏览器扩展和同源脚本能够接触密钥时，才开启“在此设备记住”。
7. 点击“拉取模型”；如果上游不支持模型列表接口，可在“模型列表”中手动输入模型标识。
8. 为文本模型选择真实协议后点击“测活”，选择模型并启动后台探针；等待“信息抽取与随机码回传”通过。
9. 文本测活通过后，系统会自动追加一次“测试工具调用”，等待“Agent 工具调用通过”。这一步会用代表性画布参数检查 Function Calling 兼容性，不会执行画布写操作；如果需要重做，可以在同一弹窗手动点击“测试工具调用”。只通过普通文本测活不能证明创作台工具可用。
10. 打开“模型选择”，为文本、图片、视频和音频分别选择默认模型。没有接入的能力可以暂时留空。

如果管理员删除或停用了当前模型渠道，或旧画布只保存了没有渠道前缀的同名模型，选择器会显示“需重新选择”并在供应商调用前停止；系统不会自动换到列表第一条渠道。重新选择一个带当前渠道归属的模型后再测活即可。

进入画布后，Agent 文本模型选择器右侧也有“测活”按钮；它会默认把当前选中的渠道模型置顶，适合边调试边重新验证。Agent 正在等待或执行时该按钮会锁定，避免在同一轮预算之外并发启动探针。

普通 AI 配置快照、画布、导出包和云同步不会包含 API Key。开启“在此设备记住”只是把密钥从普通配置中隔离到账号级持久密钥区，并不等于硬件保险库：恶意浏览器扩展、同源 XSS 或能够读取该浏览器用户目录的人仍可能取得它。共享电脑请保持默认设置，并把密钥原件保存在独立密码管理器中。

“渠道默认协议”只负责给新模型预填。真正生成前仍要确认每个模型的协议与能力一致，不能只凭模型名称猜测接口。

如果选择“OpenAI 自动兼容”且没有为文本模型单独指定协议，系统会让测活和在线 Agent 统一使用 Chat Completions；这是多数兼容网关与 Kimi 工具调用的交集。明确支持 Responses 的模型请在模型配置中显式选择 OpenAI Responses，保存后重新测活。

测活不是发送 `hi`。它会执行一次固定、低风险的运维记录信息抽取，并验证随机校验码和结构化字段；请求进入后端任务队列，慢模型可以关闭弹窗后到“任务”查看。测活会产生一次极小的真实供应商调用，但不扣平台积分；Responses、Chat Completions 与 Gemini GenerateContent 分别使用 `max_output_tokens`、`max_completion_tokens` 与 `generationConfig.maxOutputTokens` 把最大输出限制为 256 token，Kimi K3 还会使用 low 推理强度，避免简单校验沿用模型默认的超长推理预算。

测活进行中时不要用刷新、双击或多标签页反复创建。页面会在发出 POST 前保存一个不含密钥的随机提交键；如果创建响应丢失，刷新或重新点击仍会由后端永久取回同一次提交，即使原探针已经快速结束也不会变成第二次调用。后端还会把同一用户的相同自定义配置复用到原活动任务；系统渠道则按“渠道 + 模型”在所有管理员之间全局复用。即使本次提交接管的是其他标签页或管理员已经创建的活动探针，后端也会先把当前提交键绑定到原任务，再返回接管结果。页面提示“已接管原任务”或“返回原任务结果”都表示本次没有创建新任务或再次访问供应商。只有页面明确收到创建结果并清理提交键后，下一次“重新测活”才会创建新的真实请求。

测活“成功”还要看传输方式：绿色“渐进流式接收”表示更适合长分镜；“SSE 完整，但未观察到渐进分片”表示事件和结束标记合法，却无法证明上游不是在最后一次性返回，可能是短响应被网络合并，也可能是网关缓冲。 “上游返回完整 JSON”或“已回退非流式”只能说明短请求可用。供应商后台若把调用标为“非流式”，即使最终在数分钟后生成成功，中间 CDN 仍可能先返回 524；这些状态会作为管理员风险诊断显示在费用确认中，但不会禁止普通用户尝试。

长分镜仍要求真实请求使用 SSE、完整结束标记和有效 JSON；未测活、超过 7 天、疑似缓冲、非流式或未通过只会在费用确认中提示风险，普通用户仍可明确确认后创建任务。系统渠道会读取模型目录作为管理员诊断；个人自定义渠道会保留测活任务 ID供审计，但不再把成功测活当成普通用户调用的必要证明。浏览器中的绿色标签只是诊断提示，不能替代后端的配置、价格、幂等和费用安全校验。

升级到带 SSE 完整性和渐进分片诊断的版本后，旧测活结论会自动降级为未验证，因为旧解析器既没有证明结束标记完整，也没有区分实时分片与最终缓冲正文。看到“未测活”是预期风险提示；管理员可用当前版本重新执行一次，普通用户仍可在费用确认后尝试，不要手工修改浏览器存储或数据库状态伪造绿色状态。

### 2. 协议怎么选

| 能力 | 协议 | 创建路径 | 适用场景 |
| --- | --- | --- | --- |
| 文本 | OpenAI Chat Completions | `POST /v1/chat/completions` | 常见 OpenAI 兼容文本或多模态模型 |
| 文本 | OpenAI Responses | `POST /v1/responses` | 明确支持 Responses API 的模型 |
| 文本 | Gemini GenerateContent | `POST /v1beta/models/{model}:streamGenerateContent?alt=sse` | Google Gemini 原生文本或多模态输入；使用 `x-goog-api-key` |
| 图片 | OpenAI Images | `POST /v1/images/generations` | 生图、编辑和参考图 |
| 图片 | xAI Imagine Images | `POST /v1/images/generations` / `POST /v1/images/edits` | Grok Imagine 生图与 JSON 参考图编辑；最多 3 张参考图 |
| 音频 | OpenAI Audio | `POST /v1/audio/speech` | 文本转语音 |
| 视频 | OpenAI Compatible Videos | `POST /v1/videos` | 默认视频主路径，支持异步查询和参考图 |
| 视频 | NewAPI 媒体任务 | `POST /v1/videos` JSON | 通过公网媒体 URL 传递输入的 NewAPI 渠道 |
| 视频 | NewAPI Video Generations | `POST /v1/video/generations` | 使用 `image_urls`、`video_urls`、`audio_urls` 的渠道 |
| 视频 | xAI 官方视频 | `POST /v1/videos/generations` | Grok Imagine 文本生视频与单张起始图图生视频；按 `request_id` 查询，优先从私有 Files 结果下载 |
| 视频 | Gemini Veo | `POST /v1beta/models/{model}:predictLongRunning` | Google Gemini Veo 长任务 |

视频协议还决定查询路径、请求 Content-Type、参考素材字段以及轮询方式。协议选错时，常见表现是创建路径 404、字段校验失败，或任务创建成功后无法查询。

### 3. 可选：配置系统渠道

管理员进入“管理后台 → 系统渠道”：

1. 点击“新增系统渠道”，填写名称、默认模型协议、Base URL、API Key、并发策略并启用。
2. 点击该渠道的“模型管理”。
3. 使用“拉取模型”导入缺失模型，或“新增模型”手工添加。
4. 为每个模型填写模型标识、显示名称、能力、真实请求协议、计费方式和积分价格。
5. 对每个文本模型点击“测活”；通过后再启用并开放给普通用户。
6. 只有已定价且启用的模型才应提供给普通用户。

系统模型会占用用户积分。正式开放前要同时验证模型调用、定价、退款、超时和并发限制，不要只验证“模型出现在下拉框”。

## 七、完成第一条生成任务

渠道测活通过后，再使用同一文本模型完成业务闭环验证：

1. 打开左侧“画布”。
2. 点击“新建画布”。
3. 在画布底部点击“添加节点 → 文本”。
4. 在文本节点输入：`请用三句话整理一个新品短视频的项目 Brief，不要编造商品参数。`
5. 点击“生成”。
6. 等待节点从生成中变为成功。
7. 打开左侧“任务”，确认能看到同一任务的状态、模型、时间、费用和日志入口。
8. 在画布中按 `Ctrl+S` 或 `⌘S` 保存。

如果这一步成功，说明登录态、Web 代理、后端、渠道配置、任务队列、上游文本模型和结果回填已经形成闭环。此时再分别增加图片和视频模型。

### 图片验证

1. “添加节点 → 图片”。
2. 输入一条不涉及真实品牌和肖像的测试提示词。
3. 确认尺寸和默认图片模型。
4. 点击“生成”。
5. 成功后悬停节点，使用“下载”检查原文件。

### 视频验证

1. “添加节点 → 视频”。
2. 确认已选择可用的视频模型和对应协议。
3. 填写短提示词，先用供应商支持的最短时长和较低规格进行验证。
4. 点击“生成”，然后在“任务”页面观察排队、运行、轮询和完成状态。

视频是异步任务。离开画布或后端短暂重启后，支持持久轮询的任务会继续查询原供应商任务，不应重新创建一笔上游请求。

### 短剧分镜验证

1. 在画布添加“分镜脚本”节点，填写一段短剧情，或在“任务”页面选择 Agent 分镜。
2. 点击生成后阅读费用确认：系统会先发起一次文本请求；只有模型已经返回、但 JSON 结构校验不通过时，才会自动修复一次。
3. 使用自定义 API Key 时，一次分镜任务最多可能形成两次供应商调用；使用系统渠道时，用户仍按当前任务显示的积分价格结算，但平台运营方仍可能承担两次上游调用成本。
4. 最近 7 天确认过渐进式 SSE 的模型更适合慢推理长分镜；未测活、过期、SSE 疑似缓冲、非流式或失败会在费用确认中显示风险，但不会直接阻止普通用户发起调用。用户仍可确认本次费用并观察真实供应商结果，失败或费用待核对时按页面提示核账后再显式重试。官方 Kimi/Moonshot Chat 分镜会额外启用 `response_format: {"type":"json_object"}`，K3-LS、K2.7 Code/K2.6 等兼容别名不注入这个扩展，只使用结构化提示词并由后端做字段校验；普通兼容网关也不会收到供应商专用字段。后台分镜首轮和一次授权修复各有 4096 token 上限，默认生成 3–5 镜，优先在常见上游网关时限内完成；需要更长内容时拆成多次分镜任务。Kimi K3 长分镜会使用 low 推理强度；新安装默认允许文本任务等待 15 分钟、分镜任务总计等待 30 分钟。影视 Agent 页面没有四分钟固定倒计时，会按 5 秒间隔跟踪后台终态，断网、429 或 5xx 后自动退避恢复；关闭面板或刷新后仍按持久会话继续。不要重复提交同一请求。
5. 成功提示若显示“已使用一次授权修复”，可在任务日志中核对第二次请求；若修复后仍不合法，任务会失败且不会再发起第三次请求。

#### 手动交付模式：停在视频生成前

新安装或没有保存过工作模式的用户会默认进入“手动交付”。如果你已经保存过其他模式，或上游视频模型很慢、经常返回 524，也可以在画布顶部的“工作空间”切换为“手动交付”。这个模式把短剧画布的边界固定在：

```text
结构化分镜 → 分镜图 → 视频提示词 → 手动交付
```

具体操作：

1. 先生成并检查分镜表，确认每个镜头都有视频提示词。
2. 生成分镜图并挑选最终首帧；图片任务仍走 MingWant 后端队列和费用确认。
3. 在分镜节点点击“复制视频提示词”，或打开全屏分镜表后勾选镜头再复制。复制内容是可读文本，不是需要手工维护的 JSON。
4. 到你的网页视频工作台逐镜上传对应分镜图，粘贴视频提示词，选择模型、时长和画幅后再手动提交。
5. 生成结果回到项目后，通过上传/素材入口保留原镜头编号，并在项目或画布中记录结果；不要把外部网页的成功提示当成项目审查通过。

如果从画布空状态选择“一句话生成影视项目”，专业模式下影视 Agent 会同时写回剧本、场景、风格板、结构化分镜脚本和原有镜头配置；手动交付模式则直接走一次有界短 Agent 调用，只写入可编辑的分镜脚本节点，再继续上述“分镜图 → 视频提示词 → 网页工作台”路径，不需要重新手工录入模型返回的 JSON。

手动交付模式不会显示短剧批量“生成视频”按钮，也不会因为复制提示词而创建视频任务。切回“专业模式”后，才会恢复画布内的视频节点和生成控制。通用视频节点仍可单独使用，但应继续遵守费用确认、持久任务和 524 待核对规则。

在“手动交付”模式输入“搭建短剧工作流/生成分镜”时，创作台始终只发起一次有界短文本请求：不依赖 Function Calling；最近测活明确为非流式时会发送普通 JSON 请求，不再强制附带 `stream=true`。网页会把模型返回的 JSON、Markdown 或“镜头/画面/动作”格式解析为 3–5 镜头的可编辑 script 节点，不会因为测活通过而进入后台长分镜任务，也不会创建视频任务。生成后复制每行的分镜图提示词和视频动作提示词到网页工作台即可。文本请求截断或完全无法识别镜头时会停止并提示重试；要生成完整影视项目，请切换到“专业模式”，并使用真正支持渐进式 SSE 的渠道完成测活。

结构修复只处理已经收到的非标准 JSON，不是网络重试。首次请求遇到 524、连接中断或响应状态不确定时，系统不会自动进入修复，也不应由用户立即重新生成；先到供应商后台核对原请求和账单。

任务失败或取消时，后端会把任务终态、影视会话失败状态和一条固定 ID 的失败消息一起持久化；即使旧版 Worker 曾留下“任务已失败、会话仍 active”的数据，重新查询会话也会按当前任务终态自愈，并返回真实阶段、进度和错误。页面若持续显示生成中，应先打开任务中心核对原任务，不能用再次提交来解除等待。

### 在线 Agent 验证

1. 打开画布右侧 Agent，切换到“在线”。
2. 输入一个明确的小任务，例如“读取当前画布并整理节点连线”。
3. 发送确认会显示该模型最近一次 LLM 测活结论。绿色“渐进式 SSE”表示更适合慢推理；黄色“未测活/已过期”和红色“SSE 疑似缓冲/非流式/未通过”是管理员诊断警告，普通用户仍可在费用确认后调用。若提示“最近一次测活不是当前模型/协议”，说明诊断对象与当前选择不一致；可以直接尝试，也可以先让管理员为当前模型重新测活。注意：该测活验证的是固定文本抽取和 SSE 传输，不等于上游一定支持在线 Agent 所需的 Function Calling / `tool_choice`。文本测活通过后系统会自动在后台创建一次可恢复工具诊断，沿用同一渠道、协议和中转路径发送固定的无副作用 `probe_extract_record`，只检查工具名、参数和随机校验码，不执行画布写操作；也可以在测活弹窗内手动重做。系统渠道的工具结论由管理员共享维护；尚未诊断或诊断失败的普通短 Agent 会明确提示风险并默认只允许 1 次调用，但不会在建连前被探针状态拦截。手动交付短剧仍只做一次有界纯文本整理，不依赖工具诊断，浏览器会把 JSON、Markdown 或“镜头/画面/动作”格式解析为 script 节点。自定义渠道仍可在明确预算下尝试未验证模型。普通在线 Agent 的 Kimi/Kimi 兼容 Chat 会按当前意图缩小工具档，工具执行后的下一轮会沿用同一档并保留 Kimi 需要的 `reasoning_content`（仅保留在内存协议上下文，不展示、不写入日志）；如果普通兼容模式下仍没有返回工具调用，本轮会停止且不会执行画布操作，也不会自动重试。
4. 选择本轮文本推理预算：`1 次`适合慢模型或只执行明确工具，`2 次`适合一次工具加一次总结，也是流式模型的默认值；只有复杂任务才选择`4 次`。网页不再给在线 Agent 工具编排请求注入固定的 2048/4096 token 输出上限，模型按自身能力和渠道策略决定长度；Kimi 工具编排仍使用 low 推理强度。较长响应仍可能触发供应商或网关的 524，已知非流式或测活失败的模型会默认选中 1 次，但这不能消除首轮 524 风险。

确认预算后，页面会先保存用户消息、预算进度和本轮冻结的渠道绑定，再发出模型请求；如果浏览器存储失败，页面会明确显示“未调用模型”，不会让你在没有恢复记录的情况下继续产生供应商费用。
5. 发送后会话中会常驻显示“已使用 / 已授权”的调用数。工具等待确认期间不能并行发送另一条 Agent 消息；拒绝工具或达到预算后不会继续调用模型。
6. 如果收到上游 408、499、500/502/503/504/524 等服务异常，或发生连接中断，本轮会立刻停止，不自动发送下一次模型请求。先核对供应商后台或系统请求明细，再决定是否创建新请求。只有错误明确写着“调用供应商前、尚未调用”时才属于安全的本地等待失败。
7. 慢模型等待期间会显示红色“停止”按钮。它只中断当前网页连接，不能保证供应商停止执行或计费；确认停止后，本轮会记录为费用待核对，并且不会自动发起下一次请求。

如果模型完整结束却没有文本和工具，或首轮在要求工具时只返回普通文本，系统会把本次调用记入预算并停止。这通常表示该模型/网关没有正确实现 Function Calling、忽略 `tool_choice`，或在输出上限内始终没有形成工具调用；Kimi Chat 还可能是在 `auto` 兼容模式下没有遵循首轮工具要求。它不是成功的画布操作，也不会触发下一轮。在线诊断会同时显示“请求的工具选择”和“实际发送的工具选择”，便于区分协议拒绝与模型未选工具。短剧入口对 Kimi 只发送影视入口工具，完整画布快照由后台任务接收，不再让无关 Schema 和快照拖慢首个工具调用。兼容网关若在工具调用前返回可见说明，下一轮会按原 assistant 消息一并回传；内部 `reasoning_content` 仍只留在内存协议上下文。

如果错误明确写着“供应商返回输出截断”或“未完整状态结束”，说明供应商已经给出终止状态，不是 524 式连接不确定；当前调用仍可能计费，但系统不会执行可能截断的工具参数。Gemini 原生 GenerateContent 还会把 OpenAI 工具 Schema 裁剪为 Gemini 支持的参数子集；若仍提示工具参数不兼容，请检查模型是否支持原生 Function Calling。可以把一次画布操作拆小或换用更擅长 Function Calling 的模型，但网页不会再用固定 token 上限截断供应商请求。

Kimi Chat 在工具调用前产生的 `reasoning_content` 会由系统仅在当前内存工具循环中回传，满足后续调用的协议上下文；界面、会话历史和诊断日志不会显示这段内部推理。刷新页面或丢失待确认工具上下文时，系统仍会停止而不是缺少该状态后盲目续发。

使用系统渠道时，同一条用户消息的每个模型轮次都有固定请求标识。浏览器或代理丢失响应后，即使同一逻辑调用被再次送达，后端也会在占用渠道并发和调用供应商前返回 409，数据库中只允许原计费订单。这个 409 代表“重复调用已被阻止”，不代表后端保存了旧模型正文；先查看原请求明细和供应商账单，不能为了绕过 409 手工换一个标识立即重试。只有用户确认原调用已经结束并明确发起新操作时，新消息或新轮次才会使用新标识。

系统与个人自定义渠道的同步请求在新安装中默认可等待 35 分钟；如果部署曾经保存过“资源与策略”，请由管理员检查“同步模型中转超时”是否仍为旧的 10 分钟。系统渠道等待并发槽位也包含在这个总时限内，但只有真正发出上游请求后才存在供应商费用风险。这个值只决定 MingWant Studio 愿意等多久：像供应商后台标记为“非流式”、并在约 5 分钟返回 524 的请求，必须改用真正持续输出 SSE 的接口或渠道，调大本地数字无效。

这个预算只计算在线 Agent 自身的文本推理。批准生图、视频、音频或影视分镜工具后，工具创建的生成任务仍有自己的费用和调用边界；影视分镜最多还会包含首轮请求与一次事前授权的结构修复。

在线 Agent 正在等待模型、执行工具或等待工具确认时，不要收起面板、切换 Agent 模式或离开画布。系统会拦截站内跳转和面板收起；刷新、关闭标签页时浏览器也会弹出离开警告。若确实要离开，先停止当前模型等待，或处理完工具确认。后台影视项目是持久任务，页面关闭后可恢复查询，不要把它和网页在线 Agent 的即时连接混为一谈。

### 本地 Codex Agent 验证

1. 按插件说明启动本地 Canvas Agent，再从画布右侧 Agent 切换到“本地”并连接。
   插件自动打开时会使用 `/canvas?mode=new#agentUrl=...&agentToken=...`；`#` 后凭据不会发送给画布服务器，页面读取后立即清除。不要把 Token 改放到查询参数，也不要从公开的 `/config` 期待读取 Token 正文。
2. 页面只有在本地 Agent 已确认收到当前画布快照后才显示连接成功；初始同步失败会停止连接，不允许直接发送。
3. 输入“读取当前画布并列出选中节点”，确认返回内容与页面一致。每次发送前页面都会再次等待最新快照同步，不能降级成使用旧状态。
4. 执行一个需要确认的画布写操作。页面应先完成本地修改并把新快照同步给 Agent，再回传“工具完成”；这样 Agent 的下一步不会基于修改前的画布。
5. 如果出现“画布同步失败”或“工具结果回传失败”，连接会被主动断开。先检查本地 Agent 进程、地址和 token，再核对画布是否已经发生本地修改；需要时使用“撤销 Agent 批次”，确认状态后再重新连接，不要盲目重复工具调用。

连接 Token 只保留在当前浏览器会话，关闭全部相关标签或浏览器后需要重新从 Agent 启动输出取得。所有本机请求都使用 `X-Canvas-Agent-Token` 请求头，网络面板的请求 URL、画布导出和诊断日志中不应出现 Token。无论是自动还是手动连接，写工具都默认保留二次确认。

图片工具栏只展示已有真实实现的操作。“放大”用于提升图片像素尺寸；旧偏好里遗留的 `superResolve` 占位项会被忽略，不再显示只有“暂未实现”的入口。

## 八、认识五个主要入口

- **制作项目**：管理电商短视频或短剧项目、素材、画布和持久化工作流进度。
- **画布**：自由创作、15 条带货模板、节点连接、批量生成和画布导入导出。
- **提示词库**：选择明想预设并生成创意、图片或视频提示词。
- **任务**：查看生成状态、失败原因、计费、取消和视频手动恢复；所有“重试”都会创建新的供应商请求，确认费用风险后才会重新入队。
- **素材**：管理文本、图片、视频、音频和 3D 模型，可引用到项目或画布。

正式项目不要只留在自由画布里。使用“制作项目”建立项目后，再从项目详情创建关联画布，素材、工作流步骤和生成结果会更容易追踪。

### 取消和重试的费用边界

- 取消“排队中”任务时，系统通常能在供应商请求发出前停止并退回冻结积分；任务可能正好被 Worker 领取，因此确认框仍会提示竞态风险。
- “运行中”只说明 Worker 已领取任务，不等于请求已经发给供应商：如果取消事务确认任务仍在本地预检阶段，系统会明确写明未调用并退款；一旦请求已经发送、旧版本状态无法判断，或首轮已完成并进入结构修复准备，取消只能停止本系统继续等待和处理，任务会保留“供应商可能继续执行、费用待核对”的说明，此时不要马上重试。
- 在画布生成按钮点击“停止”后，节点会保持锁定并显示“正在确认后台取消结果”，直到后端返回取消/失败终态；不能把停止页面轮询当成已经取消。控制请求最多等待 30 秒，响应丢失时系统会重新读取原任务；若仍无法确认，节点会明确保留费用风险，必须去任务中心核对。
- 刷新页面或重新打开画布后，只要节点仍绑定排队中、运行中或尚未回填的后台任务，生成按钮都会显示“后台任务进行中”并保持禁用。先等待恢复链路或打开任务详情处理原任务，不要通过刷新绕过锁定。
- 即使两个标签页或两个 Web 实例同时提交了同一画布节点与同一生成操作，后端也会复用原活动任务 ID，不会再创建第二张计费订单。看到原任务返回属于幂等保护，不是新任务创建失败。
- 创建影视 Agent 会话时，浏览器会先把随机请求键、原提示词和不含明文密钥的配置指纹写入本地画布，再调用后端；落盘失败时不会发出请求。创建响应丢失或页面刷新后，重新进入原画布会在模型配置未变化时复用原键接管，后端还会恢复“会话已保存但任务尚未创建”的中断窗口。配置变化时恢复会暂停，画布副本也不会接管原任务；遇到这些提示应去原画布或任务中心核对，不能重新创建来解除等待。
- 从节点或批次明细显式取消某个后台任务时，页面只停止该任务的本地轮询；同一批次其他任务继续跟踪，也不会因为停止轮询再次调用一次取消接口。
- 在任务中心、画布单节点、批量镜头或脚本分镜点击重试时，系统会重新读取旧任务及其计费状态。旧任务仍在排队/运行、已经成功、费用仍为保留/执行中/待核对，或后台状态查询失败时，都不会创建新请求。
- 只有旧任务处于失败或已取消且平台计费已结清，系统才会再次显示费用确认；自定义渠道即使没有平台计费订单，只要错误说明表示 408/499/524、连接中断、费用待核对或同一任务已有成功计费调用，服务端也会先拦截。确认后创建的是一笔新的供应商请求，不是继续原请求；524 或非流式中断仍要先到供应商后台核账。
- 如果旧任务其实已经成功，应先从任务详情恢复或同步结果。不要用“重新生成”解决画布回填延迟。

## 九、保存、导出与分享

### 画布保存

- 使用 `Ctrl+S` 或 `⌘S` 主动保存当前画布。
- 登录状态下，画布会尝试同步后端；`localForage` 继续作为缓存和后端不可用时的降级存储。
- 页面提示“已保存在本地、云端同步失败”时，不要清浏览器数据；先恢复后端，再重新保存。

### 导出备份

1. 返回“画布”列表。
2. 选中一个或多个画布。
3. 点击“导出”，保存 ZIP 压缩包。
4. 需要恢复时使用页面上的“导入”。

导出包适合保存画布结构和关联本地媒体，但不能替代后端数据库、后端数据目录和 OSS 的完整备份。

### 只读分享

画布的分享功能会创建只读链接。停止分享后旧链接会立即失效，原画布不会删除。分享前仍应检查画布中是否包含 API Key、客户合同、未公开商品资料、肖像素材或其他敏感内容。

## 十、第一次失败怎么排查

| 现象 | 先检查 | 正确处理 |
| --- | --- | --- |
| 页面打不开 | Web 进程或容器、实际配置的 Web 端口 | 查看启动脚本最终地址和 `docker compose ... ps`；默认端口才是 3000 |
| Docker 提示找不到 `dockerDesktopLinuxEngine` 管道 | Docker CLI 存在，但 Docker Desktop Linux Engine 未启动 | 启动 Docker Desktop，等待 Engine running；也可运行 `scripts/start-local.ps1` 获取启动前诊断 |
| 启动脚本提示 `Access is denied` / `permission denied` | 当前 Windows 账号没有访问 Docker Engine 的权限，或 Docker Desktop 尚未完全启动 | 完全退出并重新打开 Docker Desktop；必要时将账号加入 `docker-users` 组后重新打开 PowerShell。脚本不会因此创建或删除容器和数据卷 |
| 启动脚本提示 Web 端口被占用 | 该端口由本项目以外的进程监听；脚本尚未创建或修改容器 | 停止提示中的占用进程，或先执行 `$env:CANVAS_HTTP_PORT = "3001"` 再运行脚本；不要直接反复执行 Compose |
| Compose 构建停在 `go build` 或 `tsc --noEmit` | 这是源码编译错误，不是 Docker Engine、账号数据或供应商 API 故障；先看输出中第一条具体文件/行号 | 修复第一条编译错误后再执行同一条 Compose 命令；不要删除卷、`backend-data` 或重新注册账号来绕过构建失败。Web 构建未完成前不会进入健康检查阶段 |
| Compose 构建停在 `resolve image config for docker-image://docker.io/docker/dockerfile` 或 `TLS handshake timeout` | Docker 正在拉取远程 Dockerfile 语法前端时遇到 Docker Hub 网络超时 | 当前 Dockerfile 已移除这项非必要远程依赖；先更新到当前源码后重跑原 Compose 命令。若随后停在 `FROM` 基础镜像拉取，再检查 Docker Hub 网络或配置企业/局域网镜像源，不要删除数据卷 |
| Web 构建在 `bun install` 出现 `Integrity check failed`、`cdn.npmmirror.com` 404 或大量 `ConnectionRefused` | 依赖锁文件的镜像 CDN 返回了损坏或不完整的 tarball | 当前构建会把锁文件中的镜像地址切换到 `NPM_REGISTRY`（默认 npmjs.org）；重跑当前源码即可。若仍失败，临时设置一个实际可访问的 npm 注册表，不要关闭完整性校验或删除数据卷 |
| API 返回连接失败 | Docker 模式检查 Web 地址下的 `/api/health`；源码模式再检查后端进程、8080 和 Vite 代理 | Docker 不单独发布宿主机 8080；先按当前运行方式检查正确地址，再确认后端使用正确数据目录 |
| `/api/health` 返回 503 | 数据库、Redis/协调器或 Worker 调度不可用 | 查看 `checks` 中失败项和 Backend 日志；修复依赖后等待健康恢复，不要继续提交生成任务 |
| 登录后像全新系统，或脚本提示 Compose 项目标识变化 | 后端数据目录、Docker 卷、仓库目录名或 `COMPOSE_PROJECT_NAME` 变化 | 立即停止写入；恢复原目录/项目标识并找回原卷，不要删除标识文件或继续注册新账号 |
| 拉取不到模型 | Base URL、API Key、模型列表接口 | 保留原列表，按供应商文档手工输入模型标识 |
| 自定义渠道提示 CORS，或浏览器网络面板直接出现供应商域名 | Web 静态资源仍是旧版本、缓存未更新，或部署把请求绕过了同源 Backend | 先确认媒体生成请求指向当前站点的任务 API、在线 Agent/模型目录指向当前站点的 `/api/ai/*`；更新 Web 镜像并清缓存，不要给供应商开放宽泛 CORS |
| 创建请求 404 | 模型协议与 Base URL 拼接 | 对照协议表和供应商真实创建路径 |
| 401/403 | API Key、渠道权限、供应商账户 | 更新密钥或权限；不要反复重试同一错误配置 |
| 429 | 上游额度、频率或本系统并发 | 降低并发、等待冷却并检查账户额度 |
| 文本请求返回 408、499、500/502/503/504/524，或连接中断 | 上游网关或模型服务异常，原请求可能仍在生成并收费；供应商显示“非流式”说明 `stream=true` 没有形成真实 SSE | 不要立即重试；先核对 API 日志和供应商后台，确认没有继续执行或计费后再决定是否新建请求；长推理应更换真正流式的接口或渠道 |
| 图片、音频或视频显示“等待超时” | MingWant Studio 停止等待不等于供应商停止执行；视频可能已经保存上游任务 ID | 不要立即重试。视频先打开任务详情使用“手动查询任务”；图片、音频或没有上游 ID 的视频先核对供应商后台、任务账单和平台计费状态 |
| 显示“等待渠道并发槽位超时”，并明确“没有调用供应商” | 请求在其他任务占满渠道时耗尽本地等待时限，尚未发出上游请求 | 本次没有供应商费用；确认预留积分已退回或退款状态正常，等待已有任务结束后再重新提交 |
| 提示“流式响应没有完整结束”或 `stream_incomplete` | 上游事件损坏、读取中断、响应超限，或关闭连接前没有发送标准完成标记 | 该轮不会把半截内容交给 Agent，也不会自动继续；系统渠道查看待核对订单和模型测活状态，自定义渠道先核对供应商账单，再修复 SSE 协议 |
| 系统渠道返回 409“同一请求标识” | 同一逻辑模型调用已经受理、结束、退款或处于费用待核对，重复提交被幂等门禁拦截 | 本次没有再次调用供应商；查看原请求和账单，不要手工换标识绕过。确需新调用时由用户确认后发送一条新的 Agent 消息 |
| 在线 Agent 长时间等待或第 N 次调用失败 | 慢模型仍在推理、系统渠道流未透传或供应商网关已超时 | 查看会话中的调用预算和请求明细；需要中断时使用红色“停止”并按费用待核对处理，不要直接收起或刷新；失败后系统不会自动继续 |
| 画布停止生成后显示“正在确认后台取消结果” | 页面正在等待取消终态，或取消响应丢失后正在读回原任务 | 不要再次生成；等待节点回填取消/失败状态。若提示“取消结果无法确认”或原任务仍运行，到任务中心核对，不要刷新后立即重试 |
| 本地 Agent 显示画布同步或工具回传失败 | 本地 Agent 已退出、地址/token 失效或桥接请求超时 | 系统会断开连接以阻止旧状态继续执行；先核对画布是否已有本地修改，必要时撤销，再恢复 Agent 后重新连接 |
| 分镜提示“首轮结构校验未通过” | 模型已回答，但结果不是可用 JSON | 已授权时系统只自动修复一次；未授权的 API 调用不会发送第二次请求，可根据任务日志调整模型或提示词 |
| 视频创建 524 或连接中断 | 上游任务可能已创建并收费 | 不要立即重试；有供应商任务 ID 时先到“任务”详情使用“手动查询任务”，否则先核对供应商后台 |
| 内容审核失败 | 提示词或素材违反上游策略 | 修改提示词后新建任务；原任务不能直接重试 |
| 视频失败但有供应商任务 ID | 原上游任务可能仍存在 | 先“手动查询任务”，确认无法恢复且计费已结清后再决定重试 |
| 画布结果未出现 | 任务成功但本地同步失败 | 刷新任务详情并重新同步；不要重复创建上游任务 |

## 十一、快速开始验收清单

- [ ] Web、后端和必要依赖使用预期端口。
- [ ] `/api/health` 的数据库、协调器和 Worker 三项全部为 `ok`。
- [ ] 后端明确使用正确的持久化数据目录或 Docker 卷。
- [ ] 第一个账号是管理员。
- [ ] 至少一个渠道拥有可用 Base URL、API Key、模型和正确协议。
- [ ] 文本任务能够创建、运行、完成并回填画布。
- [ ] 已理解分镜任务可能包含一次事前授权的结构修复，524 不属于结构修复。
- [ ] 长分镜费用确认会显示最近 7 天渐进式 SSE 诊断；未测活、过期、疑似缓冲、非流式或失败时仍允许普通用户明确确认后调用，真实上游错误和费用待核对会阻止自动续跑并要求安全重试。
- [ ] 在线 Agent 发送前可选择 1/2/4 次文本推理预算，达到预算或网关失败后不会自动续跑。
- [ ] 在线 Agent 发送确认能显示当前模型最近一次流式测活状态；非流式、未通过或未测活时默认只授权 1 次并允许真实尝试，管理员可据此判断是否更换为支持 SSE 的渠道处理长任务。
- [ ] 在线 Agent 慢请求可明确“停止等待”，并理解停止浏览器连接不等于供应商停止执行或计费；请求中无法误收起面板或丢失工具确认上下文。
- [ ] “任务”页面能看到状态、日志和计费信息。
- [ ] 当前画布已保存，并完成一次 ZIP 导出。
- [ ] 已理解视频任务应先恢复查询、再考虑重新生成。
- [ ] 未把数据库、Redis 或后端内部端口直接暴露到公网。
