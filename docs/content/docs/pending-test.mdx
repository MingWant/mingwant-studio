## UI/UX 与异常容错

- 分别注入数据库、Redis、对象存储、解密和运行时配置故障，确认未知 5xx 响应只包含稳定中文提示与 `X-Request-ID` 对应的请求编号，Backend 内部日志可用同一编号和路由模板定位；响应不得出现 DSN、文件路径、内网主机、底层连接文本或密钥。明确的 400/401/403/404/409 业务错误及上游 524 费用待核对提示仍需保留原有可操作语义。
- 触发一个未写响应的 panic，确认客户端收到标准 `{ code, data, msg }` 500 且正文无 panic 信息；服务端恢复日志不得包含 Cookie、Authorization 或完整请求头。携带 OAuth code、签名 URL 查询参数访问接口后检查常规访问日志不含查询字符串；Linux.do 回跳失败的地址栏只出现安全提示和请求编号。公开画布不存在时继续返回固定 404，而数据库、解密或存储故障必须返回脱敏 500，不能伪装成不存在。
- 在 HTTPS 外层代理覆盖 `X-Forwarded-Proto` 后分别检查 `/`、静态资源、`/api/health`、OAuth 302、公开画布 JSON 与资源文件：Web 页面必须具有 CSP、`nosniff`、`SAMEORIGIN`、Referrer、Permissions Policy 和一年 HSTS；直接 HTTP 本地访问不得发送 HSTS，Backend 8080 直连响应必须使用 `default-src 'none'`、`frame-ancestors 'none'` 与 `DENY`。尝试从外部站点 iframe 嵌入工作台应被阻止，同源正常导航和公开分享链接仍可打开。
- 在启用 CSP 的生产镜像中验证首屏主题无闪烁且控制台没有内联脚本违规；依次运行画布人脸识别、MediaPipe WASM、FFmpeg 本地合片、Blob 图片/音视频、外部登录页背景视频、HTTP/HTTPS OSS 签名资源、本地 `127.0.0.1` Canvas Agent、WebSocket/SSE 长连接和文件下载。全部可用且不得添加通用 `unsafe-eval`；若外层 CDN 覆盖或合并响应头，最终浏览器收到的策略仍只能有一套语义一致的有效 CSP。
- 分别以 `CANVAS_CORS_ORIGINS=*`、带路径、查询参数、账号信息、非 HTTP(S) URL 和精确 HTTPS/本地开发来源启动 Backend：前五类必须在连接数据库前拒绝启动，精确来源正常。经外层代理访问时，同协议同 Host（包括 3000/8443 等非标准端口）请求可用，跨协议、伪造 `X-Forwarded-Host`、未配置的其他 localhost 端口和普通外站 Origin 必须返回 403；显式配置的可信跨域来源仍能携带 Cookie。无 Origin 的 CLI 写请求保持可用，但同时携带 `Sec-Fetch-Site: cross-site` 的写请求必须在业务处理前拒绝，OAuth 顶层 GET 回调不得受影响。
- 正常退出后确认 `Set-Cookie` 同时包含空值、负 `Max-Age`、过去的 `Expires`、`HttpOnly`、`SameSite=Lax`，HTTPS 部署还包含 `Secure`，对应服务端会话已删除。注入数据库删除失败后再次退出：浏览器 Cookie 仍立即过期，接口返回“服务端会话撤销失败”而非假成功；管理员清理残留会话后旧 Cookie 不得继续认证。
- 为同一账号依次建立 21 个登录会话并预置过期记录，确认新登录、过期清理和旧会话裁剪在 SQLite/PostgreSQL 中原子完成：数据库只保留最近 20 个且新 Cookie 一定有效，最旧会话与全部过期记录失效。侧栏点击“退出其他会话”后，其他浏览器和设备立即变为未登录，当前浏览器继续可用；重复执行显示没有其他会话，不得把当前会话一并删除。
- 管理员分别修改用户密码、角色和启停状态，确认全部旧会话失效并在审计元数据中记录 `sessionsRevoked`，只改显示名或邮箱时不强制退出。让数据库拒绝删除 `auth_sessions` 后再修改安全字段，接口必须失败且用户密码、角色、状态均保持原值；不得重现忽略删除错误后仍保存的情况。
- 让 `admin_audit_events` 缺失或拒绝写入后，分别执行账号安全字段修改/停用、公告发布/关闭、系统渠道与模型增删改、模型成本/售价调整、邮件/Linux.do/开放注册/OSS 设置、分镜模板增删改、运行/积分策略修改与重置、人工调账、兑换码创建/禁用和待核对订单结算/退款；接口必须失败，登录态、账号、公告、设置、渠道、模型、兼容清单、测活状态、余额、流水、兑换码和订单处置全部回滚。正常成功时每次操作只产生对应审计，元数据不得包含 API Key、访问密钥、密码、Client Secret、Base URL、供应商正文或完整提示词；渠道和账单返回不得依赖事务提交后的额外查询。让两位管理员同时打开邮件、Linux.do、OSS 或策略页面，后保存的一方必须因版本过期收到 409，尤其不能让空白密钥字段恢复旧凭据。再在 PostgreSQL 及多连接 SQLite 中并发降级/停用不同管理员，最终必须至少保留一个可用管理员，死锁或冲突请求应整体失败且不留审计。
- 在 Redis 多实例环境从多个 IP 对同一用户名/邮箱连续登录失败，确认账号级 10 分钟上限跨 IP、跨实例累计，Redis 键只含 SHA-256 摘要而无账号原文；再从同一 IP 请求多个账号，确认独立 IP 上限仍生效。登录限制返回 `Retry-After: 600`，一小时注册/验证码限制返回 `3600`，一分钟业务限制返回 `60`。SQLite 单实例预置大量已过期限流键、过期并发 Token 和空 scope，跨过清理间隔后发起一次请求，确认旧状态被回收且活动窗口/槽位不受影响。
- 使用可控 SMTP 服务分别模拟连接超时、连接后不再响应、STARTTLS/认证/RCPT/DATA 失败和成功：连接阶段应在约 12 秒内结束，已连接流程在约 30 秒内结束；公共响应只能显示统一的注册邮件不可用提示，不能包含 SMTP 主机、内网 IP、用户名、数据库错误或服务器原始响应。配置带协议/端口的 Host、非法加密方式以及 `none + 用户名/密码` 必须在保存时拒绝，无认证的明确明文中继配置仍按管理员选择处理。
- 发送验证码前确认旧有效码与新 pending 记录在同一事务中切换；让 SMTP 失败、发送后进程中断、`sent_at` 更新失败以及失败记录删除失败，新码都必须因 `sent_at IS NULL` 无法验证，旧码也保持失效。正常发送后仅最新码可用；连续从不同 IP/Backend 实例输错 5 次必须锁定，第 5 次之后即使提交正确码也不能注册。并发两次使用同一正确码、替换邮箱或用途时只能有一个匹配账号成功创建。
- 对同一收件人跨 IP 请求验证码，确认每分钟只允许一次且 Redis/本机键中没有邮箱原文；同一 IP 对多个邮箱仍受后台小时上限。已注册与未注册邮箱的成功响应结构和文案一致，前端不得据此直接判断账号存在；验证码激活失败时明确提示稍后重新获取，不把已发送但不可用的码伪装为成功。
- 在允许剪贴板写入和拒绝剪贴板写入两种情况下测试复制；只有真实写入成功才提示“已复制”，失败时应明确提示手动复制。

## 生成任务、计费与存储优化

- 从创作台普通文本节点发起后端生成，确认即使任务输入未携带内部输出上限，Chat Completions、Responses 和 Gemini 请求仍分别带 `max_completion_tokens`、`max_output_tokens` 或 `generationConfig.maxOutputTokens: 2048`；Chat Completions 的 Kimi K3/K3-LS 还带 `reasoning_effort: low`。让模型测活成功但推理较慢时，确认普通文本在有界输出内完成或明确按截断/费用不确定停止，不再因为无界输出等到上游 524；分镜专用的 4096 上限和手动短剧路径不被覆盖。

- 构造一次返回两张内联图片的供应商成功结果：第二张使用无效 Base64、超过单文件额度或让总额度预留失败时，确认第一张尚未写入本地/OSS，数据库没有 ready 资源且每日上传预留全部释放。再让两张都通过预检、第一张落盘后第二张存储失败，确认失败任务的 `result_json` 保留第一张资源引用与第二张内联正文、第二张保持同一 pending 对象身份；立即点击“恢复已保存结果”，确认不产生供应商请求或新订单，只覆写原对象键并完成第二张，第一张资源、资源总数和每日上传量都不重复。把原任务合法重试为新订单后，应生成新的资源而不是复用上一笔付费尝试。

## 本地 Canvas Agent 稳定性

- 用新版插件打开 `/canvas?mode=new#agentUrl=...&agentToken=...`，确认 Web/Nginx 访问日志和 Referer 都不含 Token，页面读取后地址栏立即移除 fragment；未登录时应先把凭据安全收进 `sessionStorage`，登录跳转的 `next` 不得带凭据。关闭全部相关标签后 Token 应消失，`localStorage`、画布云同步、导出包和诊断日志中均不得出现；旧版 `?agentToken=` 链接应立即清除、不得写入 `sessionStorage` 或自动连接，并在登录后显示更新插件警告。
- 在浏览器网络面板确认 `/events`、`/canvas/state`、`/canvas/result`、Codex turn 与会话管理请求都只用 `X-Canvas-Agent-Token`，请求 URL 不含 `token`；本地 Agent 对仅携带 `?token=` 的请求返回 401，网页对非 `127.0.0.1` / `localhost` / `::1` 地址在发送 Token 前拒绝。让事件流持续跨越多个分片并依次发送 `hello`、`tool_call`、`agent_event`、心跳，确认前端逐事件解析且断流、非 SSE、401、超 32MB 单事件都会明确断开。通过安全启动链接自动连接后，写工具仍必须进入网页确认，不得自动关闭确认开关。
- 启动本地 Agent 后连接画布，确认 SSE `hello` 到达时页面先显示“正在同步画布”，只有 `/canvas/state` 返回 `{ ok: true }` 后才显示连接成功；分别模拟网络错误、401、500、非 JSON、`ok: false` 和超过 15 秒无响应，页面必须明确记录原因并断开，不能开放发送或静默保留假连接。
- 快速连续修改节点、连线、选择和视口，延迟较早的状态请求并让较新的请求先具备发送条件，确认快照仍严格串行到达 Agent，最终状态始终是最新画布；某次失败后重新连接或后续重试仍可继续同步，不会让失败 Promise 永久堵塞队列。
